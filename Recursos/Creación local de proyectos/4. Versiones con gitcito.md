# Gitcito: porque Ctrl+Z no es una estrategia de respaldo

[[README|Volver sin hacer force push]]

Git no evita que rompamos cosas. Nos permite saber cómo las rompimos, conversar sobre el cambio y recuperar el rumbo sin buscar una carpeta llamada `proyecto_bueno_copia_7`.

- [[Semana1/CLASE 1|Ramas y Pull Requests]] — Tu pequeño universo para trabajar sin convertir `main` en una pista de pruebas de fuegos artificiales.
- [[Proyecto/3. Guía de Contribución y Estándares del Proyecto|Convenciones del equipo]] — Para que el historial diga algo más útil que «cambios», «más cambios» y «ahora sí».
- [[Recursos/Stack y entorno|Versiones y lockfile]] — El acuerdo para que todos instalemos el mismo elenco de dependencias, en vez de estrenar una temporada distinta en cada computadora.

> [!warning] El conflicto no se resuelve eligiendo al favorito
> Antes de pulsar «aceptar ambos cambios», lee qué hizo cada persona y habla con tu compañero. Dos versiones incompatibles juntas no forman automáticamente una versión superior.

Trabaja en una rama, revisa el diff y abre un PR pequeño. El compañero que revisa tu código merece contexto, instrucciones para probarlo y, si la cosa estuvo difícil, al menos un buen chiste. Las contraseñas no se incluyen como material adicional.
